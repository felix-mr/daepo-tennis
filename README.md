# 대포클럽 대진표 · 경기 기록

GitHub Pages 화면과 Firebase Firestore 공동 경기 기록. 로그인 없이 조회·점수 입력·수정한다. `noindex`는 검색 노출 제한 요청이며 접근 제한은 아니다.

## 화면

- `/`: 날짜별 대진표 목록. 기본 클럽 디자인.
- `/2026-10-10/`: 이번 주 대진표, 전체/개인 대진, 점수 입력과 결과. 젠인 토우지 컨셉.
- `/2026-10-03/`: 지난 대진표. 고죠 사토루 컨셉과 당시 대진 보존.
- `/builder/`: 고정 멤버 선택·게스트 추가 → 자동 대진 미리보기 → 날짜별 확정·공유. 남복·여복·혼복 고정 페어의 정확한 1·2·3경기 또는 전체 경기 선택.
- `/schedule/?date=YYYY-MM-DD`: 웹에서 확정한 대진, 개인 일정과 공동 점수 입력.
- `/records/`: 전체 누적·회원 회차별·날짜별 고정 멤버 순위, 개인 기록, 파트너별 성적, 경기 기록. 전체·남자·여자 선택. 기본 클럽 디자인.
- `/setup/`: 신규 회원 프로필과 회차 명단 반영. 기존 프로필·경기 기록은 삭제하지 않고 재실행 시 중복 등록하지 않는다.

10월 10일은 조아라·김영진·김규석 불참. 남자 게스트 김규현·정상현·김진수(야닉), 여자 게스트 추진영 참석. 클럽 일정 08:00~11:00, 전원 4경기. 서명렬은 08:00~10:00 4경기 연속 후 종료하며 층 이동 없음. 나머지 11명은 2회 휴식, 연속 휴식과 4연속 경기 없음. 남복 6경기·혼복 4경기·여복 2경기. 남자 각 혼복 1경기·남복 3경기, 여자 각 혼복 2경기·여복 2경기. 여복은 성주은·추진영 vs 박정민·정가영으로 고정하며 이 두 여복 페어만 반복 허용. 층 이동 개인 최대 2회·전체 9회.

10월 3일의 시간 조건과 대진은 해당 날짜 설정에만 유지한다.

## DB 구성

Firestore는 회원 신원, 회차별 회원 명단, 경기 결과를 보관한다. 기존 날짜의 일정은 Git에 보관하고, 웹에서 새로 확정한 일정은 Firestore에 보관한다. 컨셉 정의와 회원 회차 설정은 Git에 보관한다.

```text
users/{고정 멤버 ID}
  name, gender, memberType: "fixed", createdAt

membershipPeriods/{회차 ID}
  period, label, memberIds, startsOn, endsBefore, updatedAt

schedules/{YYYY-MM-DD}             # 웹에서 새로 확정한 일정, 생성 후 변경·삭제 불가
  schemaVersion: 1, date, membershipPeriod, theme, createdAt, sourceDraftId
  startMinutes: 480, roundMinutes: 30, roundCount: 6
  players, fixedPlayerIds, profiles, quotas, availability
  lockedPairs: [{players: [ID, ID], games: 1 | 2 | 3 | "all"}]
  matches, roundParticipants, floorPlan, genderPlayers, playerNames
  lockedPairTargets, lockedPairKeys, teamKeys   # 검증용 파생 정보

scheduleDrafts/{임의 ID}                     # 검증 중인 불변 대진, 확정 목록에 노출하지 않음
  대진 정보, createdAt

scheduleDrafts/{임의 ID}/validation/{검증 ID}  # 원본에 귀속된 생성 전용 검증 문서
  date, createdAt

schedules/{YYYY-MM-DD}/matchResults/{r타임-f층}
  date, round, floor
  teamA, teamB                    # 고정 ID 또는 이번 주 게스트 참가 ID
  teamANames, teamBNames          # 당시 표시 이름 보존
  fixedPlayerIds                 # 경기 당시 고정 회원 ID 보존
  scoreA, scoreB                  # 0~99 정수
  outcome                        # teamA / teamB / draw
  updatedAt                      # 서버 수정 시각
```

고정 ID는 이름이나 로그인과 무관하게 유지한다. `data/players.json`은 역대 회원의 신원을 보존한다. 현재 등록 대상은 11명: p001 서명렬, p002 김영진, p003 나창은, p004 박세준, p005 이재원, p006 조아라, p007 성주은, p008 박정민, p009 정가영, p010 김규석, p011 위형종. 회차 회원 자격과 주별 참석 여부를 분리하므로 불참자는 ID를 유지하며 해당 주 경기에는 포함하지 않는다. `memberType: "fixed"`는 회원 프로필 종류이며 현재 가입 상태는 `membershipPeriods`로 판단한다. 게스트는 날짜별 참가 ID와 이름을 경기 기록에 보관하며 `users` 문서를 만들지 않는다.

`outcome`은 점수 비교로 정한다. 높은 점수 팀의 두 선수는 승리, 낮은 점수 팀의 두 선수는 패배, 같은 점수는 네 선수 모두 무승부다. 점수가 없거나 저장되지 않은 경기는 집계하지 않는다. 0:0도 저장하면 무승부다.

- 전체 경기 수 = 승 + 무 + 패
- 승률 = 승 / 전체 경기 수. 무승부 포함. 경기 수 0이면 `—` 표시.
- 승점 = 승 × 3 + 무 × 1. 패배는 0점.
- 순위는 승점 → 승률 → 승수 순. 모두 같으면 이름순.

순위는 경기 결과에서 계산하므로 수정 시 승패와 승점이 중복 누적되지 않는다. 같은 경기는 하나의 문서를 갱신한다. 다른 주차의 기록은 보존하지만 매 수정 이력을 따로 쌓지는 않는다. 게스트와 치른 경기도 경기 당시 고정 회원의 경기 수·승률·승점에 반영한다. 탈퇴 후 같은 ID로 게스트 참가한 경기는 고정 회원 성적에서 제외한다.

선수 선택 시 같은 팀에서 함께한 파트너별 경기 수·승무패·승률·선택 선수의 승점을 표시한다. 선택한 기간을 적용하며, 경기 수 순 또는 승률 순으로 정렬할 수 있다. 파트너는 고정 회원과 게스트 모두 포함한다. 선택 선수가 게스트 신분으로 참가한 경기는 고정 회원 성적처럼 제외한다. 일반 게스트는 방문 날짜별 ID로 구분하므로 같은 표시 이름이어도 다른 방문의 기록을 자동으로 합치지 않으며, 카드에 방문 날짜를 표시한다. 파트너 성적은 이미 저장된 팀 ID·점수·회원 자격에서 계산하므로 별도 문서나 입력은 필요하지 않다.

네 선수 모두 게스트인 경기는 대진만 표시한다. 점수 입력칸과 저장 대상에서 제외하며 기록 화면에도 표시하지 않는다. 고정 멤버가 한 명이라도 있으면 양팀 점수를 입력한다.

## 웹에서 대진 만들기

날짜에 해당하는 실제 회원 회차 명단을 불러온다. 첫 화면은 다음 토요일, 고정 멤버 전원 참석이며 지난주의 불참·지각·조퇴 조건은 복사하지 않는다. 게스트는 이름·성별을 입력하고, 멤버와 게스트 모두 참석 여부를 선택한다. 날짜를 바꾸면 일반 게스트 ID를 새 날짜 기준으로 만들고 개인 조건·페어를 초기화한다. 해당 날짜에 회원 회차가 없으면 생성을 막는다.

현재 범위는 08:00~11:00, 30분씩 6타임, 1·2층 복식, 참석자 4~16명, 개인 2~4경기다. 기본 11명은 모두 4경기(총 11경기), 인원이 많으면 코트 수에 맞춰 경기 수를 낮춘다. 경기 수·참석 시간을 개인별로 조정할 수 있다.

고정 페어는 남복·여복·혼복 모두 가능하며 최대 8개다. 1·2·3경기는 그 횟수만 함께 뛰고 나머지 경기는 다른 파트너와 뛰도록 한다. 전체 경기는 두 사람의 개인 경기 수가 같아야 한다. 한 사람이 서로 다른 파트너와 각각 일부 경기만 고정할 수도 있다. 겹친 페어의 합이 개인 경기 수를 넘거나 공통 참석 시간이 부족하면 안내한다. 네 명뿐인 성별 집단에서는 고정 페어의 상대팀도 반복될 수 있다. 지정한 고정 횟수는 반복 허용 옵션과 관계없이 정확히 지킨다.

생성기는 별도 작업으로 최대 약 3.5초 탐색한다. 시간 안에 찾지 못했다는 안내는 불가능 판정이 아니며 다시 만들거나 조건을 조정할 수 있다. 연속 휴식 회피, 최대 3연속 출전을 적용한다. 5경기 추가 배정 또는 시간·전체 페어 조건상 연속 출전이 필요하면 해당 예외를 미리보기에서 표시한다. 층 이동은 개인 최대 2회다. 미리보기에서 참석·조건을 수정하면 이전 대진을 무효화한다.

12명 미만은 기본 4경기인 고정 멤버 중 무작위로 최대 5경기를 배정해 가능한 코트를 채운다. 게스트와 직접 지정한 경기 수는 바꾸지 않는다. 화면 변경·새로고침 때 추첨 결과를 유지하며 추가 경기 다시 추첨 버튼으로 새로 뽑을 수 있다. 참석 시간, 성별 구성, 고정 페어 및 파트너 중복 조건 때문에 5경기까지로도 채울 수 없으면 빈 코트 수와 조건을 안내한다. 12명 이상은 추가 경기 없이 배정한다.

초안은 해당 브라우저에 보관하며 JSON 파일로 저장할 수 있다. 확정 시 서버가 기존 날짜와 중복되는지 확인한다. 이미 확정한 날짜·기존 정적 날짜는 덮어쓰지 않는다. 실패·오프라인에서는 초안을 유지하고 공유 완료로 표시하지 않는다. 확정한 대진은 날짜 목록·기록 화면에서 열 수 있고 기존 점수·승패 집계와 연동된다. 게스트만 있는 경기에는 점수 입력칸이 없다.

서버는 회원 자격, 이름·성별, 참석 시간, 개인 경기 수, 중복 출전, 경기 종류, 층 이동, 페어 반복 및 고정 횟수를 검사한다. 원본 초안과 검증 문서를 단계별로 저장하고, 모든 검증이 끝나면 최종 요청에서 날짜를 확정한다. 최종 대진은 검증된 초안을 그대로 복사하며 `sourceDraftId`로 원본을 연결한다. 중간 실패·연결 끊김으로 검증이 끝나지 않은 초안은 날짜 목록이나 경기 기록에 노출하지 않는다. 원본과 검증 문서는 생성 후 수정·삭제할 수 없다. 휴식·연속 출전 선호 조건은 생성·확정 전 검사하며 조회에서 과거 대진을 숨기는 기준으로 쓰지 않는다.

빌더와 공통 화면만 다시 만들기: `python3 src/build_builder.py`. 회원·회차 변경 시 기존 전체 생성 절차로 규칙·명단도 갱신한다. 웹 생성 기능 게시에는 GitHub Pages와 Firestore 규칙을 함께 반영해야 한다. 시험 데이터는 로컬 `demo-daepo` 에뮬레이터에만 저장한다.

## 회원 회차별 변경

`data/memberships.json`에 회차 ID, 표시 이름(`label`), 실제 시작일(`startsOn`), 종료 다음 날(`endsBefore`), `memberIds`를 저장한다. 현재 명단은 사용자 설명을 바탕으로 우선 2026년 8월 1일~10월 31일 회차로 설정한다. 정확한 시작일 확인 후 기간을 수정할 수 있다. 회차는 클럽 운영 날짜에 맞춰 정하며 1~3월 같은 달력 분기로 계산하지 않는다. 예를 들어 9월 15일부터 12월 14일까지면 `startsOn: "YYYY-09-15"`, `endsBefore: "YYYY-12-15"`로 설정한다. 기간은 겹치지 않게 검증한다. 기록 화면은 한국 날짜에 적용되는 회차를 기본 선택하며 전체 누적·과거 회차·날짜를 조회할 수 있다. 회차 조회는 당시 명단, 전체 누적은 역대 회원 명단을 사용한다. 적용되는 회차가 없으면 현재 명단을 임의로 복사하지 않는다.

- 신규 가입: `data/players.json`에 사용하지 않은 ID를 추가하고 해당 회차 `memberIds`에 포함한다. 가입 전 게스트 기록은 회원 성적으로 소급 집계하지 않는다.
- 탈퇴: 다음 회차 `memberIds`에서 제외한다. `users` 프로필과 지난 회차·경기 기록은 삭제하지 않는다.
- 재가입: 같은 개인 ID를 해당 회차에 다시 포함한다. 회원으로 참가한 과거·재가입 후 경기만 누적한다.
- 회원 회차 변경 후 다시 생성·게시하고 Firestore 규칙을 반영한 다음 `/setup/`에서 회원 정보·회차 명단을 반영한다.

각 경기의 `fixedPlayerIds`는 저장 후 점수 수정으로 바꾸지 못한다. 회차 명단을 나중에 수정해도 이미 저장된 경기의 회원 자격은 유지한다. 이 필드가 없는 기존 결과는 해당 경기 날짜의 회차 명단을 기준으로 읽는다. 이미 경기한 주차의 참가 구성은 저장 기록과 대조 없이 바꾸지 않는다.

## 주차별 설정과 컨셉

- `data/players.json`: 역대 회원 ID와 이름·성별. 탈퇴해도 삭제하거나 ID를 다른 사람에게 재사용하지 않는다.
- `data/memberships.json`: 회차별 고정 회원 ID 명단.
- `data/schedules/날짜.json`: 참가 ID, 고정/게스트 구분, 대진, 시간 조건, 검증 조건, `theme`.
- `data/character-catalog.json`: 7개 작품별 주요 캐릭터 70명, 색상·테니스 문구·이미지 출처. 기존 고죠·게토·토우지 포함.
- `src/characters/`: 원본 초상화 67장. 실행 중 외부 이미지 서버에 의존하지 않는다.
- `src/build_character_themes.py`, `src/character-theme.css`: 카탈로그에서 새 컨셉 JSON/CSS 생성. 기존 세 컨셉의 디자인·이미지 유지.
- `themes/컨셉.json`: 이름, 작품, 제목, 부제, 이미지, 스타일 파일.
- `themes/컨셉.css`: 컨셉별 디자인.
- `src/scores.css`: 모든 컨셉에서 쓰는 점수 입력 스타일.

10월 3일은 `"theme": "gojo"`, 10월 10일은 `"theme": "toji"`, 10월 17일은 게토 스구루(`geto`) 컨셉으로 예약했다. `data/theme-plans.json`에 예약한 날짜는 주차 설정에서 `theme`를 생략하면 해당 컨셉을 적용한다. 날짜별 참가 명단과 대진은 별도로 확정한다. 이후 주차는 `"theme": "club"` 또는 새 컨셉 ID를 지정한다. 빌더에서 작품 → 캐릭터를 선택하면 이미지·문구를 미리 볼 수 있고 확정 대진에도 적용된다. 주술회전·귀멸의 칼날·헌터×헌터·진격의 거인·원피스·나루토·블리치 각 10명이다. 새 컨셉은 카탈로그와 로컬 이미지로 추가한 뒤 빌더를 다시 생성한다. 기록 화면과 날짜 목록은 특정 주의 캐릭터 컨셉에 묶이지 않는다.

다음 주 만들기:

1. 새 `data/schedules/YYYY-MM-DD.json` 작성. 해당 회차 회원 명단부터 확인한다. 기존 회원 ID 유지, 일반 게스트 ID는 해당 날짜로 생성한다. 탈퇴한 회원이 게스트로 참가하면 기존 개인 ID를 사용할 수 있다.
2. 대진·시간 조건·컨셉 지정. `conditions.fixedWomenDoublesPairs`에 여복 고정 페어를 설정하면 모든 여복에서 해당 페어를 지키며, 지정된 두 사람의 여복 페어 반복만 허용한다. 다른 페어는 반복할 수 없다. 화면에 강조할 페어만 `display.womenDoublesPairNotes`로 선택할 수 있으며, 대진 제약은 그대로 유지한다.
3. `python3 src/build.py --date YYYY-MM-DD` 실행. 날짜를 생략하면 설정 파일의 최신 날짜를 생성한다.
4. 생성된 HTML, 설정, `firebase/schedules.json`, `firebase/firestore.rules`를 함께 보관한다. 지난 날짜 HTML은 덮어쓰지 않는다.

이미 결과가 있는 날짜의 팀 구성을 변경할 때는 저장된 결과의 팀 정보와 먼저 대조해야 한다. 기존 점수를 다른 팀에 자동 이전하지 않는다.

## Firebase 연결

웹 앱 설정은 `firebase/firebase-config.json`. 서비스 계정 키가 아닌 웹 앱 식별 설정이다. Analytics는 초기화하지 않는다. [Firebase 웹 연결 문서](https://firebase.google.com/docs/web/setup)

Firebase 프로젝트 `daepo-b3b51`의 Firestore Database → 규칙에 `firebase/firestore.rules`를 반영해야 한다. GitHub Pages 배포만으로 규칙이 반영되지는 않는다.

규칙은 공개 조회를 허용하며, 쓰기는 기존 등록 주차와 웹에서 확정한 대진의 경기 점수·결과, 설정된 회원 회차 내 토요일의 새 대진 최초 확정, 사전에 정한 회원 프로필 최초 생성, 설정에 등록된 회차 명단 반영으로 제한한다. 점수 범위, 점수와 결과 일치, 팀 ID·이름, 경기 당시 회원 ID, 회차 명단 내용, 서버 수정 시각을 검사한다. 경기 삭제, 팀 변경, 등록된 멤버 수정·삭제, 다른 경로 쓰기는 허용하지 않는다. 기존 규칙이 있다면 보존하며 합쳐야 한다. [필드 검증 문서](https://firebase.google.com/docs/firestore/security/rules-fields)

규칙 적용 후 `/setup/`에서 회원 정보·회차 명단을 반영한다. 현재 고정 ID는 로그인용 UID가 아니다. 로그인 도입 시 인증 UID와 고정 멤버 ID를 별도로 연결할 수 있다.

점수 입력은 전체/개인 화면에 실시간 공유된다. 개인 화면은 내 팀을 먼저 표시한다. 저장은 서버 확인 후 완료 표시. 다른 사람이 입력 중인 경기 결과를 먼저 변경하면 덮어쓰지 않고 최신 결과를 확인하도록 안내한다. 오프라인에서는 입력값을 유지하고 저장을 비활성화한다. [실시간 갱신 문서](https://firebase.google.com/docs/firestore/query-data/listen)

`firebase/schedules.json`은 지난 날짜의 허용 경기 정보를 보존한다. 새 주차를 추가하면 생성된 규칙도 Firebase에 반영해야 한다.
